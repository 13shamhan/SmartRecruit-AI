## Колонки и переходы

| Этап | Условие входа | Условие выхода | Кто отвечает |
|---|---|---|---|
| **Todo / К выполнению** | Есть T-ID, исполнитель, связь с US-ID, ясный результат, критерии приёмки | Есть свободный WIP-слот, исполнитель приступает | Исполнитель, согласование с командой |
| **In Progress / В работе** | Взята задача из Todo, не превышен WIP | Результат приложен ссылкой и передан на проверку | Исполнитель |
| **На проверке** | Приложены результат/скриншот/PR и критерии проверки | Проверка коллегой прошла → Done; есть замечания → In Progress с комментарием | Другой участник |
| **Done / Готово** | Критерии выполнены, проверка зафиксирована | Повторная работа только через явное возвращение с причиной | Проверяющий подтверждает |
| **Blocked / Блокировка** | **Не отдельная стадия потока**: признак у карточки в текущем статусе | Снята после проверки устранения | Владелец препятствия |

> На существующей доске есть колонка «Заблокирован». Для задания 9 предпочтительно учитывать блокировки отдельным признаком/меткой в текущей колонке. Если визуальная колонка остаётся, не исключайте её карточки из числа WIP и фиксируйте исходный рабочий статус отдельно.

## WIP-лимиты

- **In Progress:** максимум **2** карточки одновременно на всю команду.
- **На проверке:** максимум **1** карточка одновременно.
- **Todo / Done:** ограничений нет.
- Заблокированная начатая задача продолжает занимать WIP.
- При достижении лимита **не начинать новую карточку**: помочь завершить проверку, устранить препятствие или разбить задачу с согласованием команды.
- Лимит контролируется вручную, поскольку нет подтверждения автоматического запрета GitHub Projects.
- Изменения лимитов фиксировать с датой, причиной и решением команды.

**Обоснование:** два участника могут вести максимум по одной активной задаче; одна задача на ревью уменьшает очередь проверки и переключения контекста.

## Блокировки

В карточке/журнале указывать: **дату, T-ID, наблюдаемый факт, влияние, ответственного, следующий шаг и срок**. После проверки устранения оставить запись об итогах и снять признак блокировки. Риск без фактического препятствия не отмечается Blocked.

## Наблюдения за потоком

Фиксировать в одинаковое время на протяжении минимум трёх **реальных** рабочих дней: дату и часовой пояс, количество в каждом статусе, WIP/лимиты, переходы и завершённые T-ID, блокировки, ссылку на снимок. Синхронизировать Excel и GitHub на одну отметку времени.
